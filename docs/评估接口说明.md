# 评估、时间曲线、离线策略评价与验证接口

本文件说明包内已经实现、能够在 CPU 上运行的评估接口及其边界。它与《实验方案_执行手册》和《统计分析计划》配套。代码运行不等于真实研究完成；合成图像、模拟专家、模拟成本及任何合成指标均不能充当真实焊缝结果。本文不涉及 Idea 1 的视觉语言解释证据。

## 1. 模块、输入与信息隔离

| 模块 | 职责 | 可以读取的标签 |
| --- | --- | --- |
| `schema.py` | 公开 manifest、专家读取与付费日志校验 | 已经公开的专家标注，不读取私有真值 |
| `splits.py` | 试样、焊缝、原图、重复采集与设备的连接分组检查 | 只读取身份与来源元数据 |
| `evaluation.py` | 独立参考下的像素风险、图像代理指标与组件匹配 | 由调用方明确提供的独立参考 |
| `statistics.py` | 固定时间截点的阶梯 nAUC、成对簇区间、运行层不确定性、规划功效 | 已锁定轨迹的测试贡献，不选择动作 |
| `offpolicy.py` | 固定病例分布内的一次动作 IPS、SNIPS、可选 DR | 开发阶段真实记录的动作、概率、奖励与耗时 |
| `visualization.py` | 已完成独立评估的轨迹图、nAUC 区间图、动作人时图 | 已冻结的结果，不反馈到策略 |

公开数据用 `load_public_cases(manifest_path, splits=[...])` 加载。评估接口同时接受 `dict[image_id, Case]` 和 `list[Case]`。策略训练和动作选择只能收到公开像素、已有专家读取、预先可见上下文、可用动作、历史学得的成本与公开报价。

私有合成参考位于 `manifest_dir/oracle/truth.jsonl`。默认调用：

```python
from annotation_policy.evaluation import load_truth, evaluate_detector
truth = load_truth('runs/data/manifest.jsonl', split='test')
report = evaluate_detector(model, test_cases, truth, {
    'foreground_threshold': 0.35,
    'class_weights': [1.0, 1.0, 3.0],
    'matching_iou': 0.5,
    'min_predicted_component_pixels': 1,
    'n_bootstrap': 0,
    'bootstrap_seed': 17,
})
```

`load_truth` 返回 `dict[image_id, np.ndarray]`，不返回干净图像、未来动作结果或真实成本。每个参考数组必须是原始图像尺寸的二维类别图，值为 0、1、2 或 255。路径相对公开 manifest 目录。若为真实数据，必须明确传 `truth_path='independent_reference/truth.jsonl'`；不会默认把训练共识作为真实评估参考。读取函数验证图像身份、试样身份、split、尺寸、标签值及缺失参考。参考文件可包含其他 split，返回值只含指定角色。

主实验先锁定所有方法的采购序列、动作结果和模型检查点，才由 `evaluate_locked_timeline` 读取 test/reference 做评估。研究者不得在查看最终 test 曲线后重新调动作、阈值、权重或预算。开发奖励只能来自独立的 reward 开发试样。

## 2. 三类参考任务与冻结决策规则

CPU 参考任务：0 为背景，1 为圆形合成指示，2 为线状合成指示。代码中 critical 指类别 2 的软件代理，不能解释成工程危险级别。真实缺陷类别、验收规则、参考独立性和关键类代价都必须另行由领域专家确认。

`model.predict(case)` 返回 `[grid_h, grid_w, 3]` 的三类概率。每格概率必须有限、非负、和为 1。概率先通过固定规则形成类别图：若两类前景概率的最大值达到 `foreground_threshold`，选择该前景类，否则选背景；再按照均匀网格反映射回原始像素中心。合成默认 grid=8，尺寸可被 grid 整除。真实适配器需要处理自己的切块、坐标回映射和预测合并，不能将有重叠的 crop 当独立原图计数。

0.35 是软件演示参数，不是经验最优阈值。真实实验只能在 detector_val 上按预注册准则校准一次，然后冻结。`matching_iou=0.5` 与最小预测组件面积同样冻结；不得用 test 上的最好值报告主分析。

## 3. 风险与诊断指标的精确定义

对图像 i 中真实出现且可判的类别 c，令 `e_ic` 为该真实类别的像素被分到其他类别的比例。背景类的错误即背景误报为前景。图像风险为：

`r_i = sum(w_c * e_ic) / sum(w_c)`，只对该图像真实存在的已知类别求和，默认 `w=[1,1,3]`。

每个风险位于 [0,1]。先对同一试样的可评估原图风险求均值，再对试样等权平均，得到 `risk`。因此拥有更多图像/切块的试样不会自动获得更大主终点权重。这个风险会响应边界修复、类别修复和漏标修复带来的实际预测变化，但它是研究损失，不是结构失效概率。

| 输出键 | 分子 | 分母与含义 |
| --- | --- | --- |
| `risk` | 每个试样的图像平均风险之和 | 有可判图像的试样数；试样宏平均 |
| `critical_miss_rate` | 真值包含类别 2、预测在已知区域完全没有类别 2 的图像数 | 真值包含类别 2 的图像数 |
| `false_clear_rate` | 真值存在任意前景、预测在已知区域全背景的图像数 | 真值存在任意前景的图像数 |
| `critical_instance_recall` | 通过冻结 IoU 一对一匹配的类别 2 真值组件数 | 类别 2 真值组件数 |
| `normal_false_alarm_rate` | 完全已知且无真前景的图像中，预测出任意前景的图像数 | 完全已知且无真前景的图像数 |
| `mean_iou` | 3 类中有定义 IoU 的均值 | 描述性像素诊断；非论文对象检测 mAP |

组件使用 4 邻接。匹配首先最大化满足 IoU 阈值的一对一匹配数，再最大化 IoU，避免一个大预测同时“召回”多个真对象。图像层的“预测到任意关键类”不保证检测到了全部关键缺陷，所以必须同时查看实例召回、定位误差和失败图像。

未知值 255 不进入像素风险，也不进入已知区域的预测前景判定。全未知图像风险为 `null`；整个试样均不可判时，该试样主风险无法估计并单列。关键阳性/缺陷阳性分母为 0 时率为 `null`，不是 0%。报告 `unknown_pixels`、`known_pixels`、不可评估试样数以及 `undefined_metrics`。对于部分未知区域的阴性解释要谨慎：代码只能描述已知参考域。

缺失预测不能删掉图像。实现对仍有可判标签的缺失预测给 `risk=1`，保留原队列，增加 `missing_predictions`；图像缺陷代理按未给出前景预测处理。次要混淆矩阵对缺失输出采用全背景占位，因此必须与缺失计数共同解释。全未知参考仍为 `null`，不能通过缺失预测制造“可评估”。

核心 `per_specimen` 是后续配对与簇 bootstrap 的数据，而非只有汇总平均数。字段包括：

```text
risk_sum, image_count, cohort_images, image_ids, risk, reference_sha256
critical_misses, critical_images, false_clears, defect_images
critical_instances_matched, critical_instances
normal_false_alarms, normal_images, missing_predictions
known_pixels, unknown_pixels
```

`reference_sha256` 为该试样各图独立参考内容及身份的摘要。时间曲线会检查参考摘要、图像身份与参考分母一致。摘要只能发现文件/队列变化，不能证明参考本身由合格专家独立标注。

## 4. 固定预算阶梯 nAUC 与真实超时

轨迹每条事件保存：

```json
{
  "minutes": 0.0,
  "risk": 0.5,
  "per_specimen": {"specimen_001": {"risk_sum": 0.5, "image_count": 1}}
}
```

上例只展示关键字段；完整文件应直接使用评估器产生的全部 `per_specimen` 字段。也可将 `risk/per_specimen` 放入事件的 `evaluation` 子对象。第一个事件必须是 0 分钟的基线；后续是严格递增的累计已完成人时。

`step_risk_auc(events, horizon_minutes=60)` 积分右连续阶梯函数：模型在一次动作完成、标签更新并训练完成后才变更，两次更新之间维持前一模型。早停时最后可用模型持续到共同 H。完成于 H 的新模型可以计入 H 时终点，但不回溯降低 H 前的曲线面积。完成于 H 之后的动作在该 H 分析中完全没有质量收益；代码报告 `future_events_ignored`，不会通过线性插值把未来收益提前计入。

例如基线 risk=1，动作于第 5 人分钟完成并使 risk=0，在 H=10 时 nAUC=0.5；若动作直到第 12 分钟才完成，则 H=10 的 nAUC=1。这是计时规则的手算例子，不是真实实验结果。

真实专家任务可能超过报价。实际 `cost_minutes` 必须完整保留，不删除超时任务、不截断实际耗时、不假装任务在报价时间完成。公开报价只是选择前可知预算；合成环境保证实际成本不超过上限，真实适配器则记录 `quote_overrun_minutes=max(0,actual−quote)`。日志校验对 `is_synthetic=False` 且超时记录精确一致的事件允许通过并给警告。失败、无效重拍、无法裁决等同样保留正耗时；若未交付新标签，旧模型继续工作。横轴是专家人时，不是 GPU 时间、自然经过的墙钟时间或并行专家任务的简单完成时刻。

若实际工作流同时安排多位专家，需要先按预注册的资源累计规则重构事件；不能把两位专家各 5 分钟误记成 5 人分钟。训练计算延迟另报：当前主横轴只计专家劳动，若论文声称实际响应时间，应额外包含训练和等待延迟的墙钟分析。

## 5. 成对区间、多个采购运行与多重检验

```python
from annotation_policy.statistics import trajectory_summary, compare_trajectories
summary = trajectory_summary(events, 60, n_bootstrap=10000, seed=17)
comparison = compare_trajectories(
    baseline_events, full_events, 60,
    n_bootstrap=10000, n_permutations=10000, seed=17,
)
```

`trajectory_summary` 验证每个预算点使用完全相同的测试试样、图像和参考域，计算每试样 nAUC，再以试样为单位 bootstrap。`compare_trajectories` 保留配对关系，两方法每次抽到同一试样及其全部图像、预算记录。方向固定 **B−A**：上例即 Full−baseline，负值有利于 Full。若预测缺失而参考仍在，最坏风险保留了固定分母；若中途参考/队列改变，函数直接拒绝。

CI 为 percentile 95% 区间；代码默认 2000 次，正式分析可设 10000 次，smoke 可设 100—200 次。零分母不做伪造区间；有效重采样不足 20 次、独立试样不足 2 个时不给区间。全零或完全相同的观测可能产生退化区间，这不是总体风险必然为零的证明。

配对置换将整个试样的 A/B 贡献交换，使用双侧加一校正 p 值。解释依赖于零假设下适当的块交换性，不自动等同于对自适应策略进行随机试验。优先报告预注册效应、区间和研究设计。返回的 `predeclared_family_holm_p` 是固定三项诊断族：nAUC、critical_miss_rate、false_clear_rate；真实方案中的“单一主比较”“H2保护性层级”“其他基线/消融族”仍按《统计分析计划》执行，不应把这个便捷输出误当所有消融已经校正。

**单条已训练采购轨迹的试样 CI 条件于该策略、初始模型和该次动作结果。** 它不覆盖策略训练随机性、专家执行差异、新候选池或新设备群体。不能用 200 个试样×5 个预算点×10 个 seed 宣称有 10000 个独立样本。

包内另提供 `summarize_independent_runs(records)`：每条记录必须代表一个完整的成对采购运行，含 `run_id`、不同的 `acquisition_seed`、相同 `heldout_cohort_id` 和 `horizon_minutes`、以及该运行的 `difference_B_minus_A`。它输出运行差均值、运行间 SD 和配对运行均值的 t 区间，明确条件于同一个测试队列。不得把同一轨迹的多预算点或 bootstrap 抽样当作独立运行；少于 10 个运行的 t 区间附脆弱性提示。真实独立池/专家组与合成随机种子不是同一种证据。

若真实研究同时对采购运行与测试总体推断，共享测试集形成“运行×试样”的交叉依赖。按统计计划做双重重采样或明确的混合模型；当前辅助函数分别报告两种不确定性，不自动合并为一个虚假的总体 CI。独立设备/站点太少时，也不能靠图像层 bootstrap 获得站点外推置信。

## 6. 单步离线策略评价的输入、公式与拒绝条件

OPE 的估计对象仅为：在开发日志记录的病例上下文分布内，对每个既定病例选择一次可行动作的期望奖励和成本。它不估计“从剩余池挑哪例、再选动作”的自适应预算策略价值，更不能用 OPE 均值乘采购次数替代前瞻风险曲线。

每条日志至少有：

```json
{
  "event_id": "example_001", "specimen_id": "example_specimen",
  "split": "policy_val", "is_synthetic": true,
  "available_actions": ["boundary", "class"],
  "action": "boundary", "propensity": 0.5,
  "logging_policy_probs": {"boundary": 0.5, "class": 0.5},
  "cost_minutes": 2.0, "reward": -0.01,
  "quoted_max_cost_minutes": 2.5
}
```

这是格式演示，不是观察结果。`reward=before_risk−after_risk`，允许负值；正成本包含失败。所有可用动作的 logger 概率必须完整记录。目标概率和可选 q 预测分别传 `dict[event_id][action]`，或者记录中的 `target_policy_probs`、`q_by_action`。

令 `w=π(a|x)/p(a|x)`。IPS 为 `mean(w*reward)`；SNIPS 为 `sum(w*reward)/sum(w)`；DR 为 `mean(sum_a π(a|x)q(x,a) + w*(reward−q(x,a)))`。DR 没有独立 q 时输出 `null`，不能把训练集拟合值伪装成交叉验证。成本相应给 IPS/SNIPS；`reward_per_expected_minute` 是两种单步期望之比，不是固定预算动态价值。

明确拒绝以下输入：重复事件、非开发 split、不可行动作、负/零/非有限成本、概率和不为 1、selected propensity 与完整概率向量不一致、目标对 logger 零概率动作赋正概率、q 缺动作或不完整、q/目标策略利用了本次评估试样进行训练或调参。

只检查“实际选择动作的概率大于零”不够；即使该动作本次没出现，只要目标有正概率，也必须在该病例的 logger 可行动作集中有正概率。未标注案例只允许 new_image，已有标签案例才允许相应修订，因此六类操作并非同一病例的通用六臂。

`evaluate_ope` 必须收到目标策略出处：预声明固定策略可用 `{'mode':'predeclared','description':'预先冻结的规则'}`；拟合策略用 `mode='held_out'`，显式记录 `training_specimen_ids`、`tuning_specimen_ids`，两者必须与所有 OPE 试样不交。q 也使用同样的 held-out 元数据。空 tuning 列表必须明确写出。元数据检查不能证明研究者没有偷看评估奖励，必须保留训练日志、配置版本和时间戳审计。

当前实现直接支持“外部试样留出”的 q/target，不假装自动实现全流程 cross-fitting。若采用交叉拟合，要在上层按试样分折训练，每折生成真正排除该折的模型，逐折调用留出 OPE，再按预注册方法合并与推断；不可仅改写 provenance 为 OOF 便声称已经完成。若 target 经 policy_val 选择超参数，则同一个 policy_val 不再是它的独立 OPE 集。

随包 CLI 的快捷模式专门新建 **只在 policy_train 拟合、固定 ridge=1 和 temperature=0.1 的模型**，在 policy_val 产生 target 概率与 q，再评价；它不加载在 policy_val 调参后的主预算模型。任何修改这些值也应在查看 policy_val 奖励前声明，否则要另留 OPE 集。模型对训练中未出现的动作不赋目标概率；如果该病例可行动作均无训练支持，则拒绝运行，需要增加随机探索日志或缩小预先声明的研究范围。

报告包含原始权重、有效样本量 `ESS=(sum w)^2/sum(w^2)`、目标支持上的最小 logger 概率、最大权重、未裁剪估计和 cap=2/5/10 的敏感性。选择 `max_weight` 后主返回值会裁剪，同时保留 `unclipped`；裁剪和自归一化带来有限样本偏差，裁剪 DR 不再自动保持通常的双重稳健性质。极低 ESS 不能支撑确认性主张。实际日志中所有目标权重恰好为 0 时 SNIPS 和奖励/分钟为 `null`，不能据 IPS 数值 0 声称目标策略没有效果。

OPE 区间仍以试样为簇，保留同一试样的多条日志，但条件于固定 target、q、上下文分布和共享开发 reward panel。共享小 reward panel 的抽样误差、策略调参过程以及未来真实专家变化不在该 CI 中。

## 7. 数据验证与防泄漏审计

`validate_dataset` 检查必需字段、相对路径、图片/标签尺寸、允许标签值、非空正报价、可用动作与当前标签状态、未标注例不暴露隐藏标签、至少 3 位不同专家的初始读取。读取唯一键为 `image_id + annotator_id + read_id`，不同专家均用 read0 合法；同一专家重复 read0 非法。重复读片不变成额外独立专家。

`check_group_leakage` 对 specimen、weld、source image、采集会话、重复采集、重复/近重复组与 parent/original image 引用做连通分量隔离：任何经中间图像间接连接的来源族都不能跨 seed_train/policy_train/policy_val/reward/acquisition_pool/detector_val/test/device_test。

即使默认 `within_domain` 协议，`device_test` 的 device_id 也必须与全部其他角色隔离；`device_holdout` 进一步要求主 test 的设备与开发数据隔离，`site_holdout` 类似。对图片可以检查 SHA256，帮助发现文件替换；来源 ID 必须全项目唯一并由实际采集记录支持。代码不能自行认出未记录的同一试样、近重复裁片或伪造来源元数据，仍需盲审与来源核对。
