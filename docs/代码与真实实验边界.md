## 2. 接真实检测器：一个窄的命令协议

`DetectorCommandAdapter` 调用本地命令列表：

```text
python your_local_detector_wrapper.py --request /abs/adapter_request.json --response /abs/adapter_response.json
```

fit 请求给出 `training_manifest`、`output_dir`、`seed`、`config`、`training_specimen_ids` 及清单 SHA256。wrapper 必须只用当前训练状态，返回 `request_id`、`status=completed`、`backend`、实际 `model_path`、`model_sha256`、同一 `training_specimen_ids`。predict 请求只给白名单图像清单及模型路径；返回实际 prediction JSONL 路径与 SHA256，每个 image_id 恰有一条。

`export_current_training_manifest(cases, output_dir)` 把付费后的当前影像、原始专家读取和当前训练 target 物化到新目录。当前标签叫 `current_labelmap_path`，不会伪装成新增专家。新图原来的 `initial_labeled=false` 被保留，当前 `active=true` 可以进入训练。提供的 `reference_adapter_worker.py` 使用这些当前 target，不能误读回原始多数标签。

协议演示可在 Python 中实际运行：

```python
from annotation_policy.dataset import load_public_cases
from annotation_policy.adapters import export_current_training_manifest, DetectorCommandAdapter
import sys

cases = load_public_cases("runs/smoke/data/manifest.jsonl", splits="seed_train")
manifest = export_current_training_manifest(list(cases.values()), "/tmp/idea02_current")
backend = DetectorCommandAdapter([sys.executable, "scripts/reference_adapter_worker.py"])
fit = backend.fit(manifest, "/tmp/idea02_adapter_fit", seed=17, config={"epochs": 60})
pred = backend.predict("runs/smoke/data/manifest.jsonl", fit["model_path"], "/tmp/idea02_adapter_predict")
```

这段只运行 CPU 参考模型。真实 wrapper 必须替换内部训练和推理，不能只改 backend 名称。该适配器验证了文件与声明边界，但没有沙箱化外部模型进程；正式研究应让训练作业根本拿不到 test/reward 的参考标签目录，并独立审计数据读取。

若采用 bbox 检测，输出记录至少为 `image_id, objects:[{class_id,score,bbox_xyxy}]`。在独立 evaluator 中实现同类别一对一实例匹配、不同 IoU 阈值、类别/严重性分母和试样风险；保留 per_specimen 接口再连接 nAUC 统计。**这部分真实 bbox evaluator 未假称在 CPU 示例中完成。** 在微型人工可数例上校验后，再与框架官方 evaluator 对照同一固定预测。

## 3. 接真实随机动作 pilot

先给每个预先抽到的病例保存一个 context JSON：当前图像/标注计算的 features、完整 available_actions、报价、split 和试样 ID。固定可行性后再随机化：

```bash
python scripts/prepare_pilot_request.py --context data/examples/public_context.json --output /tmp/idea02_request.json --protocol-id demo_only --state-version initial_v1 --seed 17
```

示例 context 是合成的，命令只生成本地请求，不代表专家已工作。真实 pilot 每个病例使用预先登记、可重现但不同的随机种子；保存完整概率向量。内建随机化是“给定病例后均匀选动作”，其 propensity 不能冒充从完整候选池选择该病例的联合概率。

专家完成后输出 completion JSON：对应 event_id、状态 completed/failed/cancelled_after_work、每位专家 active intervals、原因，完成修订还需 after_state_version、实际产物路径和 SHA256。原版本不改。导入：

```bash
python scripts/import_human_action.py --request /tmp/idea02_request.json --completion /path/to/actual_completion.json --ledger /path/to/paid_ledger.jsonl
```

人工台账为单写入者追加文件；并发多人写同一台账时应使用事务数据库，不能依赖 JSONL 文件 append 去实现锁。相同事件不得重复导入，同一人的重叠时间段会被拒绝，不同人同时工作按总人时收费。失败和真实 quote 超时完整保留；超时不应删样本、重随机化或截短时长。

## 4. 把真实重训指标连接为 reward

先固定 before 的训练集 D0＋候选当前版（若 active），after 只替换/增加该动作造成的训练状态；其余初始权重、顺序、随机种子、训练步数相同。新图在 before 不加入、after 按实际是否获得标注加入；失败或无变化不能跳过 after 来伪造“零 reward”，可复用精确相同确定模型的情形要注明。

独立开发评估生成 before/after 两份 metrics JSON：`risk`、`split=reward`、`specimen_ids`、`training_specimen_ids`、`model_sha256`、`seed`。二者必须使用完全相同的 reward 试样，不能与训练或候选重叠。policy_train 使用 reward_fit，policy_val 使用另一组 reward_tune：

```bash
python scripts/attach_reward.py --ledger /path/to/paid_ledger.jsonl --event-id ACTUAL_EVENT_ID --before-metrics /path/to/before.json --after-metrics /path/to/after.json --reward-panel reward_fit --output /path/to/one_measured_action.jsonl
```

该命令只连接已存在的结果，不能判断检测器是否实际遵守协议；训练日志、权重与原预测均须保留。没有重训指标时 `reward` 保持 null，禁止填经验估计的“该动作大概有用”。正式训练策略前合并已核验事件，按试样隔离 train/val，交给 `train_policy.py`，另审计 reward_fit/tune 不重叠。

真实 completion 记录中的 `is_synthetic=false` 必须来自真实 context。样例不能改标志后伪装真实人时。真实超时记录必须给出准确 `quote_overrun_minutes`；代码允许保留它进入成本学习，不会把难例删掉。策略可行性仍只看事前报价；如实际结束在 H 之后，H 截点只继承上一状态，不提前使用该修订。

## 5. 固定基线和实现边界

`configs/matrix.yaml` 的 17 项直接执行。参考“去分歧”消融删除存在、类别、边界、边界配对率、复读和模型—标注差异六个 feature；仍保留图像、模型不确定性和标注数量等已声明特征。它不等于改变底层共识聚合方法。若还要验证 vote aggregation 的影响，需另注册单独训练标签生成消融。

去成本排序只替换收益/成本排序为收益排序；可行性依然受事前报价约束，不能让它超预算。去 IPW 要重新拟合，不只是改最后图注。成本校正使用训练 log-cost 残差的 exp 平均乘子；这不是经过完整分布建模的置信区间，长尾真实人时还需检验。

所有比较的 initial/pilot 人时是共同沉没成本，另表报告，不藏在“60 分钟”增量预算之外不提。若 learned 方法独享一个额外 pilot、其他方法没有同等资源，则不能只比较60分钟增量曲线；需要总人时敏感性分析及 break-even 图。

## 6. 明确没有自动完成的工作

没有取得 SWRD/企业影像原文件并审计其 trial/device 元数据；没有招募专家；没有运行真实标注软件；没有取得真实 GPU 检测器权重；没有做自然分歧诊断、跨设备真实实验、LOAO、ActiveLab/DARL 忠实复现或完整双重稳健序贯策略评价。文档对这些分别给出步骤，结果模板保留 NA。

此外，完整独立采购运行的分层/双向 bootstrap 在真实方案中必须按设计实施；已有代码提供固定轨迹的试样 CI 与独立运行汇总，不声称一次合成采购轨迹就是政策层面的充分统计证据。
